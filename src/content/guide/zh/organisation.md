## 谁能打开组织页面

组织页面用来设置公司及其中的组织、人员，以及这些人的 BMO 和智能体。组织功能包含在 `team` 和 `operator` 安装中。

从侧边栏“系统服务”中的“组织”打开。这一项对平台管理员、负责人，以及获得组织记忆写入权限的人显示。不领导任何组织的成员也能查看自己的设置。在“设置”的“我的应用·工具”中点“打开”，这个页面会以选中“我”的状态打开。

## 左侧的树

树中只显示我能设置的地方。

- **“我”：** 我自己的位置。位于每个有账号的人的树的最上方。
- **“整个平台”：** 位于所有公司之上的平台本身。只有平台管理员能看到。
- **公司和组织：** 公司以建筑图标、组织以人形图标显示，下级组织层层嵌套在上级组织之下。事业部、中心、团队、小组之类的名称只是各组织的名字；如果公司设定了“类型”，会以小标记显示在名称旁边。

可以用树上方的搜索按名称或类型查找，平台管理员可以用搜索框旁的“添加公司”新建公司。选中的位置会保留在地址中，分享链接就会打开同一个地方。在手机上，点标签栏前面的按钮，树会以底部抽屉的形式打开。

## 右侧的标签页

标签页针对在树中选中的位置打开。切换标签页时选中的位置不变，换选位置时标签页也不变，因此可以沿着树往下，逐级查看同一项设置。

| 标签页 | 用途 | 谁能看到 |
|---|---|---|
| “组织架构图” | 查看和修改负责人、代理职务、成员和兼职。“添加组织”“调动组织” | 管理员、负责人 |
| “用户” | 查找人员，查看账号、所属、权限、BMO、供给和活动 | 管理员、公司负责人 |
| “职务·类型” | 公司的职务和组织类型列表 | 管理员、公司负责人 |
| “邀请” | 用“创建邀请链接”把人加入组织 | 管理员、负责人 |
| “BMO” | 公司成员的默认 BMO 和“BMO 设置权限” | 管理员、负责人 |
| “智能体” | 与组织成员的智能体有关的所有设置 | 管理员、负责人 |
| “应用与工具” | 开启和关闭哪些应用 | 所有人（在各自能设置的位置） |
| “制品存储” | 组织成员的文档保存在哪里 | 管理员、负责人 |
| “密钥保管库” | 按名称保存该位置的机密 | 我：本人；组织：管理员和负责人；平台：管理员 |
| “组织记忆” | 整个组织共享的记忆 | 管理员、负责人、获得权限的人 |
| “供给”、“套餐” | 供给策略和积分、所用套餐 | 管理员、积分·订阅负责人、负责人 |

选中“我”或“整个平台”时，该位置没有设置的标签页只会显示“此标签页没有个人设置。”或“此标签页没有平台设置。”

## “智能体”标签页

与组织成员的智能体有关的设置集中在一处。每项设置旁都有一栏，用来选择下级组织如何对待这个值（“沿用上级”“允许下级组织”“锁定下级组织”）。这些说法在“组织与委托链”一章中详细介绍。

- **“组织指引”：** 帮助组织成员的所有智能体都会收到的指示。上级组织也有指引时，会显示“上级组织的 n 条指引优先适用”。
- **“人设”：** 决定智能体是否使用人设（“使用人设”“不使用人设”）。
- **“智能体供给来源”：** 决定“个人供给”“组织供给”“平台供给”各自在这个组织中开放还是关闭。
- **“组织供给密钥”：** 由组织直接付费的 API 密钥和 Claude 账号。密钥的值只输入一次，只保存在组织专属的机密存储空间中，不会再次显示。
- **“加入时配置”：** 决定按角色给新成员几个智能体。
- **“个人设置许可”：** 决定成员能否自己进行“添加和关闭智能体”“选择提供商 · 模型”“我的指示”。
- **“组织仓库”：** 只由这个组织成员的智能体处理的仓库，以及是否允许“管理仓库”。

## “供给”标签页

查看组织的“供给策略”（按什么顺序使用哪些供给来源、每人每月上限）、正在使用的“套餐”、组织的“积分”余额和“发放积分”，以及“本月用量”。支付功能处于关闭状态，积分只能通过发放增加。

## “应用与工具”标签页

在选中的位置上，为每个应用选择“开启”“关闭”或“遵循上级组织”，并可用“锁定下级组织”对下面所有人固定。选中“我”时，只为自己开启或关闭提供给我的应用。详细内容见“应用与个人工具”一章。

## “组织记忆”标签页

写下适用于整个组织的事实后，帮助该组织及下级组织成员的所有智能体都会一起收到。

- 在“本组织的记忆”中用“添加记忆”填写内容、相关人物和主题。下级组织就同一主题重新填写时，以下级的为准。
- 打开“固定”后，下级组织不能覆盖这个主题。打开“仅限公司内部”后，在有公司外部人员的房间里不会使用。
- 成员留下的内容汇集在“提议”中，由负责人“接受”或“拒绝”。
- 用“组织记忆写入权限”可以把写入权限也给非负责人。

关于个人的记忆，只写角色、负责的工作、希望的联系方式这类组织可以知道的内容。个人情况、健康之类的内容不写。

## “制品存储”标签页

决定组织成员的文档保存在哪里。“存储位置”在什么都没设定时是“本服务器”，也可以选择 SharePoint 文档库。改动后的位置从之后保存的文档开始适用，已保存的文档留在原处。

## “密钥保管库”标签页

这里用来把 API 密钥、令牌、密码等机密交给智能体和单元，而不经过聊天房间或记录。树中每个位置都有一个存储空间。

- **“我”：** 只属于我的存储空间。“设置”中的“密钥保管库”也通向这里。
- **公司和组织：** 该组织的存储空间，由负责人和平台管理员管理。在“智能体”标签页的“组织供给密钥”中填入的密钥，也按名称保存在这里。
- **“整个平台”：** 存放整个部署所用机密的地方，只有平台管理员能打开。

无论哪个位置，列表中都只显示“已保存的机密”的名称、大小和最后修改时间，值不会在任何页面上再次出现。用“添加机密”放入新机密，用“替换”更换值；“删除”时旧值会再额外保存一次。交给智能体和设置的只是机密的名称，因此值不会留在对话中。

## 须知

- “创建邀请链接”会设定姓名、组织、角色和有效期生成链接，并立即复制。收到的人在链接中设定姓名、ID 和密码创建账号，并连接自己的设备。
- 账号准备好后，会自动生成这个人专属的 BMO、个人聊天房间，以及按“加入时配置”分配的智能体。
- 兼职不会把那个组织的设置传给这个人。设置沿着所属组织传下来。
