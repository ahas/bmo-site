## BMO는 이렇게 설치합니다

BMO는 내 컴퓨터에서 돌아가는 AI 에이전트 플랫폼입니다. 웹 콘솔에서 BMO와 대화하고, BMO는 기억(브레인)을 쌓으며 노트, 문서, 캘린더, 파일 같은 내 일을 함께 다룹니다.

BMO는 사람이 명령어를 하나씩 따라 치며 설치하지 않습니다. BMO를 돌릴 컴퓨터에서 Claude Code나 Codex 같은 코딩 에이전트를 열고, 아래 한 줄을 그대로 건네면 됩니다.

```
https://bmo.ahas.io/install.md 를 읽고 이 컴퓨터에 BMO를 설치해 줘.
```

에이전트는 설치 런북을 처음부터 끝까지 읽은 뒤 명령을 모두 직접 실행합니다. 사람에게는 사람만 가진 것만 묻습니다. 어떤 설치를 원하는지, 채팅 봇의 토큰, 콘솔에 쓸 이름과 비밀번호, 도메인, 브라우저에서 해야 하는 로그인, 그리고 컴퓨터가 관리자 권한을 요구할 때의 승인입니다. 한 단계에서 필요한 질문은 한 번에 모아서 묻습니다.

## 준비할 컴퓨터

| 항목 | 필요한 것 |
|---|---|
| 운영체제 | Linux. 패키지 이름은 Debian·Ubuntu 계열 기준입니다 |
| 프로세서 | 64비트 x86 또는 ARM |
| 계정 | root가 아닌 일반 사용자 |
| 메모리 | 16GB 이상 (적으면 빌드가 멈출 수 있어 먼저 묻습니다) |
| 디스크 | 여유 공간 60GB 이상 |
| 네트워크 | GitHub에 접속할 수 있어야 합니다 |

systemd가 없는 컴퓨터에서도 설치할 수 있습니다. 이때는 BMO의 테스트베드가 가진 감독 프로그램이 서비스를 대신 돌립니다.

## 세 가지 설치 종류

에이전트는 처음에 어떤 설치를 원하는지 한 번 묻습니다. 설치 종류는 공개 저장소의 `presets.toml`에 정의되어 있습니다.

| 설치 종류 | 무엇이 들어가나요 |
|---|---|
| `personal` (개인) | 한 사람과 그 사람의 BMO. 콘솔, 기억, 코딩 에이전트, 채팅 서비스 하나, 문서, 노트, 캘린더, 파일, 메일, 원격 데스크톱. 조직 기능과 GPU가 필요한 기능은 없습니다 |
| `team` (팀) | 개인 설치에 회사, 조직, 구성원, 방 권한, 코드 리뷰, 리서치가 더해집니다 |
| `operator` (운영자) | 공개된 모든 것. 고객의 소리, BMO의 얼굴, GPU 노드의 음성과 비전, GPU 카드 나눠 쓰기, 노드 모니터, 영상 보관함, 원격 머신 허브. GPU 머신, 도메인, 리버스 프록시가 필요합니다 |

`personal`과 `team`은 웹 콘솔 말고 BMO와 대화할 채팅 서비스를 하나 고릅니다. Telegram 또는 Discord 중 하나이고, `operator`는 둘 다 설치합니다.

## 설치하면서 묻는 값

| 값 | 뜻 |
|---|---|
| 콘솔 이름과 비밀번호 | 콘솔에 로그인할 때 쓰는 이름과 비밀번호. 직접 정합니다 |
| 콘솔 주소 | 콘솔을 여는 주소. 도메인을 쓰지 않으면 이 컴퓨터 안에서 3210번 포트의 `/bmo/` 주소로 엽니다 |
| BMO가 부를 이름 | 대화에서 BMO가 나를 부르는 이름 |
| 채팅 서비스의 내 아이디와 언어 | 채팅 서비스에서의 내 아이디, 그리고 BMO가 나에게 답할 언어 |
| 봇 토큰 | Telegram이나 Discord 봇의 토큰 |
| 원격 데스크톱 비밀번호 | 콘솔이 여는 원격 데스크톱의 비밀번호 |

비밀 값은 명령줄이나 로그, 에이전트의 답에 남지 않습니다. 에이전트는 값을 임시 파일에 적어 설치 프로그램에 넘긴 뒤 바로 지웁니다.

## 설치가 하는 일

1. 먼저 아무것도 바꾸지 않는 시험 실행으로 전체 계획을 보여 줍니다.
2. 설치 종류에 든 저장소를 모두 내려받습니다.
3. 필요한 프로그램, 포트, 입력값을 확인하고 데이터베이스와 설정 파일을 만듭니다.
4. 저장소를 하나씩 첫 배포하고, 첫 콘솔 계정과 첫 채팅 에이전트, 나만의 방을 만듭니다.
5. 모든 서비스의 상태를 확인하고, 내 방에 시험 메시지를 보냅니다.

도중에 무언가 실패해도 처음부터 다시 할 필요는 없습니다. 같은 설치를 다시 실행하면 멈춘 곳에서 이어집니다.

## 설치가 끝나면

에이전트가 콘솔 주소, 로그인 이름(비밀번호는 말하지 않습니다), 설치한 종류와 채팅 서비스를 알려 줍니다. 콘솔을 열고 로그인한 뒤, 채팅 봇에게도 메시지를 하나 보내 BMO가 답하는지 확인해 보세요.

설치 뒤에 저장소를 하나 더하는 일(예: `bmo-research`)은 BMO 자신의 일입니다. BMO는 그 저장소 하나에 대해 내가 승인했을 때만 더합니다. 새 버전은 BMO의 배포 절차로 반영됩니다.

## 올인원 데스크톱 앱

코딩 에이전트 없이 내 PC에 바로 BMO를 두고 싶다면 **BMO All-in-One** 앱이 있습니다. 개인 설치(`personal`)를 이 PC에 설치하고 실행하며, 콘솔을 앱 창에 띄웁니다. 별도 서버가 필요 없습니다.

- **요구 사항:** 메모리 16GB와 디스크 60GB의 Linux, 또는 WSL 2가 있는 Windows입니다. Windows에서는 `BMO`라는 이름의 WSL 2 배포판 안에서 돌아갑니다.
- **첫 실행:** 무엇이 어디에 설치되는지 보여 주고 동의를 받은 뒤, 컴퓨터 확인, 준비, 필요한 프로그램 설치, 입력값, 설치 순서로 한 화면씩 진행합니다. 관리자 권한은 운영체제 자신의 확인 창으로만 묻습니다.
- **실행 중:** 트레이 아이콘이 콘솔을 열고 상태를 보여 줍니다. 앱을 끝내면 BMO 서비스도 함께 멈추고, 앱을 다시 켜면 다시 시작합니다.
- **업데이트:** 앱 자체는 앱의 업데이트 기능으로, BMO의 저장소들은 서버와 똑같이 BMO 자신의 배포로 새 버전을 받습니다.

이미 BMO 서버가 있다면 **BMO 원격 제어기** 앱을 씁니다. 서버의 콘솔을 창에 띄우고, 이 PC를 BMO가 일할 수 있는 기기로 연결합니다. 두 앱 모두 [jake](https://github.com/ahas/jake) 저장소에서 만듭니다.

## 알아 두기

- 설치 런북 원문은 [install.md](https://bmo.ahas.io/install.md)이고, 설치 종류는 [bmo 저장소](https://github.com/ahas/bmo)의 `presets.toml`에 있습니다.
- 모든 설정과 비밀은 데이터 폴더 하나(`~/.local/share/bmo/data`) 아래에 모입니다.
- 이미 다른 프로그램이 쓰는 포트는 피해서 다음 빈 포트를 씁니다.
- 올인원 앱의 Windows 경로는 만들어져 있지만, 문서에 따르면 아직 실제 Windows에서 돌려 본 단계는 아닙니다.
