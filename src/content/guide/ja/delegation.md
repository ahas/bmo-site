## 委任チェーンとは

BMO の多くの設定は、上から下へひとつずつ段を下りて届きます。この流れを**委任チェーン**と呼びます。

1. プラットフォーム
2. 会社
3. 会社の下の組織（その人が属する組織まで、何段階でも）
4. 人

各段では、その段を受け持つ人（プラットフォームはプラットフォーム管理者、組織は組織長、人はたいてい本人）が 2 つのことを決めます。その設定の値が何か、そして下の段がその値を変えられるかどうかです。

ある人のチェーンは、その人の所属組織をたどります。別の組織を兼務していても、その組織の設定は届きません。

## 3 つの選択: 上位に従う、許可、ロック

組織画面の設定ごとに「下位組織」の欄があり、次のどれかを選びます。

| 選択 | 意味 |
|---|---|
| 「上位に従う」 | 上の段が決めたとおりにします。何も決めていない状態です |
| 「下位組織に許可」 | 下の組織と人が変更できるよう開いておく、という意思を示します |
| 「下位組織をロック」 | 下のすべての段がこの設定を変えられないよう固定します |

ロックは、何段階下であってもすべてに適用されます。ロックされる前に下の段が決めていた値は消されずに保管され、ロックを外すと元に戻ります。「下位組織に許可」で、上で掛けられたロックを外すことはできません。ロックは、掛けた段でしか外せません。

プラットフォーム管理者はロックの掛かった下の段にも値を書けますが、その値もロックが外れるまでは読まれません。

## 値が決まる順序

ある人に実際に適用される値は、チェーンを上から読んで決まります。

- **近い段が優先されます。** だれも値を決めていなければ、その設定の既定値が適用されます。
- **ひとつの段の中では、** その人を指定したルール、その人が属するグループのルール、その人の組織を指定したルール、その段自身の値の順に、先にあるものを使います。
- **上で掛けたロックがすべてに優先します。** ロックの下の段が決めたことは読まれません。
- **狭めることしかできない設定もあります。** 供給元のスイッチやアプリの提供のように、下の段は上で開いたものを閉じることしかできず、上で閉じたものを開き直すことはできません。

## 画面ではこう表示されます

| 画面 | 表示される言葉 |
|---|---|
| 組織画面 | 「自分で設定」、「上位組織に従いオン」のような従っている値、ロックなら「上位組織でロック」 |
| 自分の設定 | 「自分で設定」、「組織に従う」、「組織でロック」、「組織が設定 · 組織名」、プラットフォームが決めていれば「全体設定で設定」 |

「自分で設定」の行には「元に戻す」があり、自分で決めた値を消して、上から届いた値に戻せます。ロックされた設定はボタンが薄く表示されて無効になり、だれが決めたかが下に書かれます。

## 供給: 何で動き、だれが払うのか

供給とは、エージェントの 1 回の実行がどの認証情報で行われ、だれがその費用を払うかです。供給元が変わっても、エージェントが使うプロバイダーとモデルは変わりません。

**エージェントの供給元**は 3 つあり、実行はこの順に下りていきます。

1. 「個人供給」: 自分の Claude ログインや自分の API キー。自分がプロバイダーに直接支払います。
2. 「組織供給」: 自分の所属組織が登録したキーと Claude アカウント。組織が支払います。
3. 「プラットフォーム供給」: プラットフォームの認証情報。プランに含まれる利用量やクレジットで支払います。

3 つの供給元は、どれも委任チェーンの設定です。「個人供給」と「プラットフォーム供給」は最初から開いていて、組織は閉じることしかできません。「組織供給」は最初は閉じていて、プラットフォーム管理者がその会社に「この会社に組織供給を提供」をオンにすると開きます。

組織とプラットフォームは**供給ポリシー**も持ちます。ポリシーは、「個人供給」、「全体供給」、「組織クレジット」、「個人クレジット」のうち何を許可するか、どの順に使うか（「供給順序」、最後は必ず「停止」）、ひとりが 1 か月に使える組織クレジットの上限を決めます。インストールしたばかりのプラットフォームの基本ポリシーでは個人供給だけがオンで、プラットフォームが支払う供給元は、管理者がオンにするまでオフのままです。

### 自分の「供給」設定

組織画面の「供給」タブで「自分」を選ぶと、自分の側を確認できます。「設定」の「供給」で「開く」を押しても、ここに来ます。

- 「供給ログイン」: 自分の Claude ログインを追加し、順序を決めます。「供給ログインを追加」を押すとブラウザーでログインし、受け取ったコードを「認証コード」に貼り付けて「ログインを完了」を押します。
- 「供給キー」: シークレット保管庫に入れておいたキーを名前で選んでつなぎます。キーの値はこの画面に表示されません。
- 「供給順序」: 自分が使う供給元の順序とオン・オフ、個人クレジットの月の上限。
- 「今月の利用量」: 供給元ごとに、今月使った量と残りの量。

決済機能はオフになっています。クレジットは管理者やクレジット担当者の付与によってだけ増え、チャージのボタンはありません。

## チェーンをたどって届くほかの設定

| 設定 | どこで決めるか |
|---|---|
| 「組織の指針」、「ペルソナ」 | 組織画面の「エージェント」タブ |
| 「加入時の構成」、「個人設定の許可」、「リポジトリの管理」 | 組織画面の「エージェント」タブ |
| アプリ、スキル、MCP サーバーの提供とオン・オフ | 組織画面の「アプリ・ツール・スキル」タブ |
| ドキュメントの「保存先」 | 組織画面の「アーティファクトの保存」タブ |
| 「標準 BMO」、「BMO 設定権限」 | 組織画面の「エージェント」タブ（「許可」、「ブロック」、「上位組織に従う」） |
| 個人アプリの作成、ネットワーク・シークレットの使用、共有の範囲 | 組織画面の「アプリ・ツール・スキル」タブの「個人アプリ」 |
| メールサーバー | 組織画面の「メールサーバー」タブ |
| 「2段階認証を必須にする」 | 組織画面の「セキュリティ」タブ |
| 「全体の記憶を読む」、「組織の記憶を読む」 | 組織画面の「組織の記憶」タブの「読む範囲」 |

## 変えた設定が届くとき

変えた値は、次のターンから適用されます。指針とペルソナは各人の次の会話のターンから、供給元は次の実行が始まるときから、アプリは次の呼び出しと次に画面を読み込むときから反映されます。何が変わったかを別に知らせることはなく、使う側が使うたびにチェーンに問い合わせ直します。

## 知っておくこと

- だれも何も決めていなければ、人はエージェントに関するすべての個人設定を行えます。
- 上で閉じられた供給元は自分の設定で薄く表示され、「組織でブロック」や「管理者がブロック」のような理由が付きます。
- 「供給制限を適用」がオフのあいだは利用量を記録するだけで、どの実行も供給を理由に止まることはありません。
