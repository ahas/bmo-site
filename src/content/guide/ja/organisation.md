## 組織画面はだれが開くのか

組織画面は、会社とその中の組織、人、そしてその人たちの BMO とエージェントを設定する場所です。組織の機能は、`team` と `operator` のインストールに含まれています。

サイドバーの「システムサービス」にある「組織」で開きます。この項目は、プラットフォーム管理者、組織長、そして組織の記憶を書く権限を受けた人に表示されます。どの組織も率いていないメンバーも、自分の設定は確認できます。「設定」の「マイアプリ・ツール」で「開く」を押すと、この画面が「自分」を選んだ状態で開きます。

## 左のツリー

ツリーには、自分が設定できる場所だけが表示されます。

- **「自分」:** 自分自身の場所です。アカウントを持つすべての人のツリーのいちばん上にあります。
- **「プラットフォーム全体」:** すべての会社の上にある、プラットフォームそのものです。プラットフォーム管理者にだけ表示されます。
- **会社と組織:** 会社は建物の印、組織は人の印で表示され、下位組織が親組織の下に何層にも入ります。本部、センター、チーム、パートといった名前は各組織の名前にすぎず、会社が決めた「種類」があれば名前の横に小さな印で付きます。

ツリーの上の検索で名前や種類を探せ、プラットフォーム管理者は検索欄の横の「会社を追加」で新しい会社を作ります。選んだ場所はアドレスに残るので、リンクを共有すると同じ場所が開きます。スマートフォンでは、タブの列の前にあるボタンを押すと、ツリーが下の引き出しとして開きます。

## 右のタブ

ツリーで選んだ場所についてのタブが開きます。タブを移っても選んだ場所はそのままで、選んだ場所を変えてもタブはそのままなので、ひとつの設定をツリーに沿って下りながら読めます。

| タブ | できること | だれが見るか |
|---|---|---|
| 「組織図」 | 組織長、職務代行、メンバー、兼務を確認し、変更します。「組織を追加」、「組織異動」 | 管理者、組織長 |
| 「ユーザー」 | 人を探して、アカウント、所属、権限、BMO、供給、アクティビティを確認します | 管理者、会社の長 |
| 「役職・種類」 | 会社の役職と組織の種類の一覧 | 管理者、会社の長 |
| 「招待」 | 「招待リンクを作成」で組織に人を招き入れます | 管理者、組織長 |
| 「BMO」 | 会社の人たちの基本の BMO と「BMO 設定権限」 | 管理者、組織長 |
| 「エージェント」 | 組織の人たちのエージェントに関するすべての設定 | 管理者、組織長 |
| 「アプリ・ツール」 | どのアプリをオン・オフにするか | 全員（それぞれ設定できる場所で） |
| 「アーティファクトの保存」 | 組織の人たちのドキュメントをどこに保管するか | 管理者、組織長 |
| 「シークレット保管庫」 | その場所のシークレットを名前で保管 | 自分: 本人、組織: 管理者と組織長、プラットフォーム: 管理者 |
| 「組織の記憶」 | 組織全体で共有する記憶 | 管理者、組織長、権限を受けた人 |
| 「供給」、「プラン」 | 供給ポリシーとクレジット、適用するプラン | 管理者、クレジット・サブスクリプション担当者、組織長 |

「自分」や「プラットフォーム全体」を選んだとき、その場所に設定がないタブには「このタブには個人設定がありません。」や「このタブにはプラットフォーム設定がありません。」とだけ表示されます。

## 「エージェント」タブ

組織の人たちのエージェントに関する設定が、一か所にまとまっています。各設定の横には、下位組織がこの値をどう扱うか（「上位に従う」、「下位組織に許可」、「下位組織をロック」）を選ぶ欄が付きます。これらの言葉は「組織と委任チェーン」の章で詳しく説明しています。

- **「組織の指針」:** 組織の人を手伝うすべてのエージェントが受け取る指示です。上の組織にも指針があれば、「上位組織の指針 n 件が先に適用されます。」と表示されます。
- **「ペルソナ」:** エージェントがペルソナを使うかどうか（「ペルソナを使う」、「ペルソナなし」）を決めます。
- **「エージェントの供給元」:** 「個人供給」、「組織供給」、「プラットフォーム供給」のそれぞれを、この組織で開いておくか閉じるかを決めます。
- **「組織の供給キー」:** 組織が直接支払う API キーと Claude アカウントです。キーの値は一度だけ入力し、組織用のシークレット保管スペースにだけ保存され、二度と表示されません。
- **「加入時の構成」:** 新しく加わった人に、ロールごとにエージェントをいくつ与えるかを決めます。
- **「個人設定の許可」:** 人が自分で「エージェントの追加・オフ」、「プロバイダー · モデルの選択」、「自分の指示」を行えるかどうかを決めます。
- **「組織のリポジトリ」:** この組織の人たちのエージェントだけが作業するリポジトリと、「リポジトリの管理」を許可するかどうかです。

## 「供給」タブ

組織の「供給ポリシー」（どの供給元をどの順で使うか、ひとりの月の上限）、適用中の「プラン」、組織の「クレジット」残高と「クレジット付与」、「今月の利用量」を確認します。決済機能はオフになっているので、クレジットは付与によってだけ増えます。

## 「アプリ・ツール」タブ

選んだ場所で、アプリごとに「オン」、「オフ」、「上位組織に従う」を選び、「下位組織をロック」で下のすべてに固定できます。「自分」を選ぶと、自分に提供されたアプリを自分のためだけにオン・オフします。詳しくは「アプリと個人ツール」の章にあります。

## 「組織の記憶」タブ

組織全体に当てはまる事実を書いておくと、その組織と下位組織の人を手伝うすべてのエージェントが一緒に受け取ります。

- 「この組織の記憶」で「記憶を追加」を押し、内容、関係する人物、話題を書きます。同じ話題を下位組織が書き直すと、そちらが優先されます。
- 「固定」をオンにすると、下位組織はその話題を上書きできません。「社内限定」をオンにすると、社外の人がいるルームでは使われません。
- メンバーが残したものは「提案」に集まり、組織長が「受け入れる」か「断る」を選びます。
- 「組織の記憶の書き込み権限」で、組織長でない人にも書き込み権限を与えられます。

人に関する記憶には、役割、担当業務、連絡を受けたい方法のように、組織が知ってもよいことだけを書きます。個人的な事情や健康のような内容は書きません。

## 「アーティファクトの保存」タブ

組織の人たちのドキュメントをどこに保管するかを決めます。「保存先」は、何も決めなければ「このサーバー」で、SharePoint のドキュメントライブラリを選ぶこともできます。変えた保存先はそれ以降に保管するドキュメントから適用され、すでに保管したドキュメントは元の場所に残ります。

## 「シークレット保管庫」タブ

API キー、トークン、パスワードのようなシークレットを、会話ルームや記録を通さずにエージェントとユニットに渡す場所です。ツリーの場所ごとに、保管スペースがひとつずつあります。

- **「自分」:** 自分だけの保管スペースです。「設定」の「シークレット保管庫」もここにつながっています。
- **会社と組織:** その組織の保管スペースで、組織長とプラットフォーム管理者が扱います。「エージェント」タブの「組織の供給キー」で入れたキーも、ここに名前で保管されます。
- **「プラットフォーム全体」:** デプロイ全体で使うシークレットがある場所で、プラットフォーム管理者だけが開けます。

どの場所でも、一覧には「保管中のシークレット」の名前、サイズ、最後に変わった日時だけが表示され、値はどの画面にも二度と表示されません。「シークレットを追加」で新しいシークレットを入れ、「置き換え」で値を変え、「削除」すると以前の値がもう一度保管されます。エージェントと設定にはシークレットの名前だけが渡されるので、値が会話に残ることはありません。

## 知っておくこと

- 「招待リンクを作成」では、名前、組織、役割、有効期限を決めてリンクを作り、すぐにコピーします。受け取った人はリンクから名前、ID、パスワードを決めてアカウントを作り、自分のデバイスをつなぎます。
- アカウントの準備ができると、その人だけの BMO と個人ルーム、「加入時の構成」に沿ったエージェントが自動で作られます。
- 兼務は、その組織の設定をその人に引き継ぎません。設定は所属組織をたどって届きます。
