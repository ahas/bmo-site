## BMO のインストール方法

BMO は、自分のコンピューターで動く AI エージェント基盤です。Web コンソールで BMO と話し、BMO は記憶（ブレイン）を積み重ねながら、ノート、ドキュメント、カレンダー、ファイルといったあなたの仕事を一緒に扱います。

BMO は、人がコマンドをひとつずつ打ち込んでインストールするものではありません。BMO を動かすコンピューターで Claude Code や Codex のようなコーディングエージェントを開き、次のひとことをそのまま渡してください。

```
https://bmo.ahas.io/install.md を読んで、このマシンに BMO をインストールして。
```

エージェントはインストールのランブックを最初から最後まで読み、コマンドをすべて自分で実行します。人に尋ねるのは、人にしかわからないことだけです。どのインストールにしたいか、チャットボットのトークン、コンソールで使う名前とパスワード、ドメイン、ブラウザーで行うログイン、そしてコンピューターが管理者権限を求めたときの承認です。ひとつの段階で必要な質問は、まとめて一度に尋ねます。

## 用意するコンピューター

| 項目 | 必要なもの |
|---|---|
| OS | Linux。パッケージ名は Debian・Ubuntu 系を前提にしています |
| プロセッサー | 64 ビットの x86 または ARM |
| アカウント | root ではない一般ユーザー |
| メモリ | 16GB 以上（少ないとビルドが止まることがあるため、先に確認します） |
| ディスク | 空き容量 60GB 以上 |
| ネットワーク | GitHub に接続できること |

systemd のないコンピューターにもインストールできます。その場合は、BMO のテストベッドが持つ監視プログラムが代わりにサービスを動かします。

## 3 つのインストールの種類

エージェントは最初に、どのインストールにしたいかを一度だけ尋ねます。インストールの種類は、公開リポジトリの `presets.toml` で定義されています。

| インストールの種類 | 含まれるもの |
|---|---|
| `personal`（個人） | ひとりの人とその人の BMO。コンソール、記憶、コーディングエージェント、チャットサービスひとつ、ドキュメント、ノート、カレンダー、ファイル、メール、リモートデスクトップ。組織の機能と GPU が必要な機能はありません |
| `team`（チーム） | 個人のインストールに、会社、組織、メンバー、ルームの権限、コードレビュー、リサーチが加わります |
| `operator`（運用者） | 公開されているものすべて。お客様の声、BMO の顔、GPU ノードの音声とビジョン、GPU カードの共有、ノードモニター、動画ライブラリ、リモートマシンのハブ。GPU マシン、ドメイン、リバースプロキシが必要です |

`personal` と `team` では、Web コンソールのほかに BMO と話すチャットサービスをひとつ選びます。Telegram か Discord のどちらかで、`operator` は両方をインストールします。

## インストール中に尋ねられる値

| 値 | 意味 |
|---|---|
| コンソールの名前とパスワード | コンソールにログインするときの名前とパスワード。自分で決めます |
| コンソールのアドレス | コンソールを開くアドレス。ドメインを使わない場合は、このコンピューターの中で 3210 番ポートの `/bmo/` で開きます |
| BMO が呼ぶ名前 | 会話の中で BMO があなたを呼ぶ名前 |
| チャットサービスでの自分の ID と言語 | チャットサービスでの自分の ID と、BMO があなたに答える言語 |
| ボットのトークン | Telegram または Discord のボットのトークン |
| リモートデスクトップのパスワード | コンソールが開くリモートデスクトップのパスワード |

シークレットの値は、コマンドラインにもログにもエージェントの回答にも残りません。エージェントは値を一時ファイルに書いてインストーラーに渡し、すぐに消します。

## インストールがすること

1. まず、何も変更しない試験実行で全体の計画を見せます。
2. インストールの種類に含まれるリポジトリをすべてダウンロードします。
3. 必要なプログラム、ポート、入力値を確認し、データベースと設定ファイルを作ります。
4. リポジトリをひとつずつ初めてデプロイし、最初のコンソールアカウント、最初のチャットエージェント、自分専用のルームを作ります。
5. すべてのサービスの状態を確認し、自分のルームにテストメッセージを送ります。

途中で何かが失敗しても、最初からやり直す必要はありません。同じインストールをもう一度実行すれば、止まったところから続きます。

## インストールが終わったら

エージェントが、コンソールのアドレス、ログイン名（パスワードは伝えません）、インストールした種類とチャットサービスを知らせます。コンソールを開いてログインし、チャットボットにもメッセージを送って、BMO が答えるか確かめてみてください。

インストール後にリポジトリを追加すること（例: `bmo-research`）は BMO 自身の仕事です。BMO は、そのリポジトリについてあなたが承認したときだけ追加します。新しいバージョンは BMO のデプロイ手順で反映されます。

## 「はじめに」ガイド

初めてログインすると、コンソールが**はじめに**（`/start`）を開きます。BMO があなたに答える前に決めておくことを 1 段階ずつ尋ね、BMO との最初の会話で終わります。画面の上に `{n}/{m}` と進行バーがあり、「前へ」と「次へ」で行き来します。

- **プラットフォーム管理者:** プラットフォームで使える供給元がひとつもないときだけ開きます。「プラットフォーム供給」（サーバーでの Claude ログイン、プロバイダーの API キー、または OpenAI 互換アドレスの「ローカルAI」）、「接続テスト」、「既定のモデル」（ルームに答える既定のスーパーバイザーのプロバイダーとモデル）、「会社名」、「最初の会話」の順です。
- **メンバー:** 「ようこそ」、「供給」、「プロバイダー」、「接続」、「接続テスト」、「デバイス」、「最初の会話」のうち、やることがある段階だけが表示されます。組織が供給をすべてまかなうなら、供給の段階は省かれます。自分の Claude ログインやキーが必ず必要な人は、それがテストに通るまで次の段階に進めず、あってもなくてもよい人は「あとで」で飛ばします。
- **「接続テスト」**は、選んだ供給元でいま一度実行してみて、「接続済み」か、うまくいかない理由を知らせます。
- **「デバイス」**は、自分の PC がまだつながっていないとき、デスクトップアプリのダウンロードと接続コードの入力を案内します。

必ず必要な供給の段階でなければいつでも閉じられ、進めた段階は保存されます。あとで「設定」の「アカウント」にある「はじめにをもう一度見る」で、もう一度開けます。

## 招待されて参加する

`team` と `operator` のインストールでは、組織長が「招待リンクを作成」で作ったリンクを受け取って参加します。リンクを開くと、名前、ID、パスワードを決めてアカウントを作り、続けて自分の PC をつなぎます。つなぐ方法は、2 つのタブのどちらかを選びます。

- **「デスクトップアプリで始める」:** 自分の OS に合ったインストールファイルをダウンロードし（ほかの OS のインストールファイルも横にあります）、アプリが「BMO サーバーのアドレス」を尋ねたら画面に表示されたアドレスを貼り付け、アプリのウィンドウのタイトルバーに見える「接続コード」を入力して「接続」を押します。
- **「jake コマンドで始める」:** Linux・WSL 用と Windows 用の 1 行のインストールコマンドをコピーして、PC で実行します。

PC がつながるとアカウントの準備が整い、自分だけの BMO と個人ルーム、組織の「加入時の構成」に沿ったエージェントが作られます。ログインすると、そのまま「はじめに」ガイドに進みます。

**1 台の PC につながるエージェントはひとつだけです。** 同じ名前の jake がすでにインストールされている PC でデスクトップアプリを開くと、アプリは内蔵のエージェントを起動せず、インストール済みの jake がこの PC を受け持っていると知らせます。「内蔵エージェントに切り替え」を押すと、インストール済みの jake をそれ自身のアンインストーラーで外し、アプリのエージェントに切り替えます。ハブも、同じ名前での 2 つめのインストールは受け付けません。

## All-in-One デスクトップアプリ

コーディングエージェントを使わずに自分の PC へ直接 BMO を置きたいときは、**BMO All-in-One** アプリがあります。個人のインストール（`personal`）をこの PC にインストールして動かし、コンソールをアプリのウィンドウに表示します。別のサーバーは必要ありません。

- **必要なもの:** メモリ 16GB とディスク 60GB の Linux、または WSL 2 が使える Windows です。Windows では `BMO` という名前の WSL 2 ディストリビューションの中で動きます。
- **初回起動:** 何がどこにインストールされるかを示して同意を得たあと、コンピューターの確認、準備、必要なプログラムのインストール、入力値、インストールの順に、1 画面ずつ進みます。管理者権限は、OS 自身の確認ウィンドウでだけ尋ねます。
- **実行中:** トレイアイコンからコンソールを開き、状態を確認できます。アプリを終了すると BMO のサービスも一緒に止まり、アプリをもう一度起動すると再開します。
- **アップデート:** BMO のリポジトリは、サーバーと同じく BMO 自身のデプロイで新しいバージョンを受け取ります。アプリ自体は、下の「デスクトップアプリのアップデート」に従います。

すでに BMO サーバーがあるなら、**BMO リモートコントローラー** アプリを使います。サーバーのコンソールをウィンドウに表示し、この PC を BMO が作業できるデバイスとしてつなぎます。どちらのアプリも [jake](https://github.com/ahas/jake) リポジトリで作られています。

### デスクトップアプリのアップデート

- **公式のビルドは GitHub のリリースから受け取ります。** ダウンロードページもアプリのアップデートも [jake リポジトリのリリース](https://github.com/ahas/jake/releases) を読み、アップデートはアプリに入っている公開鍵で署名が確認できたものだけをインストールします。
- **静かにインストールされます。** アプリは起動したときと 6 時間ごとに新しいバージョンを確認して裏でダウンロードしておき、自分がアプリを終了するときか、アプリが何もしていないときに、ウィンドウも確認もなしにインストールします。再起動したアプリのトレイメニューに「アップデート済み · vバージョン」が表示されます。インストールに失敗すると元のバージョンで起動し直し、次の確認のときにもう一度試します。
- **チャネル:** 「設定」の「デスクトップ」で、「更新チャネル」を「安定版（デフォルト）」と「ナイトリー」から選びます。ナイトリーは毎日作られるビルドなので、正しく動かないことがあります。ナイトリーから安定版に変えても、すでにインストールされているバージョンより低いバージョンに下がることはありません。
- Linux の AppImage は自分で置き換わり、deb パッケージでインストールしたアプリは、パッケージマネージャーかダウンロードページから自分でアップデートします。

## 知っておくこと

- インストールのランブックの原文は [install.md](https://bmo.ahas.io/install.md) で、インストールの種類は [bmo リポジトリ](https://github.com/ahas/bmo) の `presets.toml` にあります。
- すべての設定とシークレットは、ひとつのデータフォルダー（`~/.local/share/bmo/data`）の下にまとまります。
- ほかのプログラムがすでに使っているポートは避け、次の空いているポートを使います。
- All-in-One アプリの Windows 向けの経路は作られていますが、ドキュメントによると、実際の Windows で動かして確かめた段階にはまだありません。
